# TypeScript and JavaScript Tree-sitter adapter

`typescript.New()` returns the concrete implementation of `pkg/parser.Parser`
for TypeScript and JavaScript under the single language id `typescript`. It
extracts an `ir.SourceFile` from the supplied UTF-8 bytes without opening the
source path, selecting binding targets or writing graph records.

## Design

| Component | Pinned version/design |
| --- | --- |
| Go bindings | `github.com/tree-sitter/go-tree-sitter v0.25.0` |
| Grammars | upstream `tree-sitter-typescript v0.23.2` (`typescript` and `tsx`) and `tree-sitter-javascript v0.23.1` |
| Grammar selection | by extension: `.tsx`/`.jsx` use `tsx`, `.js`/`.mjs`/`.cjs` use `javascript`, `.ts`/`.mts`/`.cts` use `typescript` |
| Native parser | one reusable session per worker whose language is switched per file; never used concurrently |
| Extraction | source-ordered traversal of named nodes and fields; no query files |

The profile accepts language level `4` or `5`, no preview features and no
adapter settings; JavaScript files parse under the same profile. Calls on one
`Parser` serialize through cancellable admission, `Close(ctx)` is idempotent
and parsing a closed instance returns `ErrClosed`.

## What is extracted

| IR table | TypeScript and JavaScript constructs |
| --- | --- |
| Declarations | classes (`class`, `abstract class`, class expressions), interfaces, enums and their constants, type aliases (`type_alias`) with the members of their object-type literals and their named constituents as written bases, namespaces and modules (`namespace`), functions and generators, methods, constructors, getters and setters, fields and parameter properties (`constructor(private x: T)` declares the field too), module-level variables (`variable`), locals, parameters (including destructured bindings, defaults and rest), type parameters. A destructuring or `for...of` binding is initialized by a synthesized member or element access of what it takes |
| Modifiers | `export`, `default`, accessibility, `static`, `readonly`, `abstract`, `async`, `override`, `declare`, `const`, `let`, `var`; `export { X }` and `export default X` mark the named root-scope declaration after the fact |
| Imports | every binding of an `import` statement (`default`, `*` or a named export) with the written module specifier in `Import.Module`; `import x = require("m")`, `const x = require("m")` and `const { a, b: c } = require("m")` as imports rather than variables; re-exports (`export { X as Y } from "m"`, `export * from "m"`, `export * as ns from "m"`) and the module-level `export { X }`, `export { X as Y }` and `export default X` of an imported or local binding as `re_export` imports |
| Calls | calls, generic calls (`f<T>(x)`, including the grammar's await-attached form), member calls with the receiver expression, `super(...)` as a call named `constructor`, tagged templates, `new X(...)` as object creation with the constructed type; a computed callee is named `()` |
| References | name references and member accesses with their receiver, JSX tags that name a component (capitalized or qualified), `export default X` |
| Types | named types with type arguments, predefined types as primitives, arrays, unions and intersections (a leading `\|` is unwrapped); function, structural (object literal, tuple, mapped), literal and operator (`keyof`, `typeof`, indexed access, conditional, `infer`, `this`) types with their nested types as `component` uses |
| Type uses | fields, parameters, returns, locals, generic arguments, bounds, heritage (`extends`, `implements`), constructions, casts (`as`, `satisfies`, `<T>x`), alias bodies, decorators |
| Annotations | decorators, with the decorator expression's name chain as the written type and its arguments as expressions |
| Lambdas | arrow functions, function expressions and object-literal methods as lambda sites with their parameters and body scope |
| Expressions | names, literals (regular expressions as string literals), `this`, `super`, member access, calls, parenthesized, casts, assignments (including destructuring targets), unary, binary (including the comma operator), conditional, await and yield, spread, arrays, object literals (`object_literal`), element access, JSX (`markup`), class expressions |

A file the adapter recognizes as generated output is declined before
parsing with `parser.ErrGeneratedSource` and the reason (`generated.go`): a
generation marker (`@generated`, `DO NOT EDIT`, `Code generated by`) in the
first 4 KiB on a comment line, a `sourceMappingURL` comment in the last
KiB, a bundler header, or, for files of 64 KiB and more, a mean line length
of 1,000 or a single line of 50,000 characters. The pipeline skips and logs
it; nothing in it is bound.

Coverage is `complete` when every expression and type has an explicit kind.
Syntax the adapter does not model is retained as an `unknown` expression or
type with a coverage issue, and Tree-sitter errors or missing tokens make
coverage `partial` while the surrounding declarations are still extracted.
The file, directory and `.d.ts` conventions of module resolution are the
resolver's concern, not the parser's.
